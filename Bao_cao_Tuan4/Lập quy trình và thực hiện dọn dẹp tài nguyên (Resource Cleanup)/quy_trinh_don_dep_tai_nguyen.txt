## 2. Quy trình dọn dẹp tài nguyên theo thứ tự phụ thuộc (Step-by-Step Procedure)

Để tránh lỗi xung đột phụ thuộc giữa các dịch vụ (ví dụ: không thể xóa S3 bucket khi bên trong còn chứa objects hoặc đang có tiến trình ghi log), nhóm thực hiện dọn dẹp theo thứ tự từ tầng Giám sát $\rightarrow$ Truy vấn $\rightarrow$ Metadata $\rightarrow$ Lưu trữ $\rightarrow$ Hạ tầng mạng:

| Bước | Dịch vụ AWS | Tên tài nguyên cần dọn dẹp | Thao tác thực hiện chi tiết trên AWS Console | Kết quả xác nhận |
| :---: | :--- | :--- | :--- | :---: |
| **1** | **Amazon CloudWatch** | Alarm: `daily-datalake-high-scan-alert`<br/>Log group: `/aws-glue/crawlers` | 1. Vào **CloudWatch** $\rightarrow$ **Alarms** $\rightarrow$ chọn `daily-datalake-high-scan-alert` $\rightarrow$ **Actions** $\rightarrow$ **Delete**.<br/>2. Vào **Logs** $\rightarrow$ **Log groups** $\rightarrow$ chọn `/aws-glue/crawlers` $\rightarrow$ **Actions** $\rightarrow$ **Delete log group(s)**. | Đã xóa hoàn toàn |
| **2** | **Amazon Athena** | Workgroup: `daily-datalake-wg` | Vào **Athena** $\rightarrow$ **Workgroups** $\rightarrow$ chọn `daily-datalake-wg` $\rightarrow$ chọn **Delete** (xác nhận xóa workgroup sau khi đã dừng toàn bộ truy vấn). | Đã xóa hoàn toàn |
| **3** | **AWS Glue** | Crawler: `daily-sales-crawler`<br/>Database: `daily_datalake_db` | 1. Vào **AWS Glue** $\rightarrow$ **Crawlers** $\rightarrow$ chọn `daily-sales-crawler` $\rightarrow$ **Action** $\rightarrow$ **Delete crawler**.<br/>2. Vào **Databases** $\rightarrow$ chọn `daily_datalake_db` $\rightarrow$ **Delete** (tự động xóa kèm 2 bảng `sales` và `sales_parquet`). | Đã xóa hoàn toàn |
| **4** | **Amazon S3** | Bucket: `daily-datalake-24112051-24110252-2026` | 1. Chọn bucket $\rightarrow$ bấm nút **Empty** $\rightarrow$ nhập `permanently delete` để xóa toàn bộ objects trong `raw/`, `processed/`, `athena-results/`.<br/>2. Chọn lại bucket đã rỗng $\rightarrow$ bấm **Delete** $\rightarrow$ nhập tên bucket để xác nhận xóa. | Đã làm rỗng & Xóa bucket |

## 3. Kịch bản tự động hóa dọn dẹp bằng AWS CLI (Automated Cleanup Script)

Bên cạnh thao tác trên giao diện Console, nhóm xây dựng kịch bản dòng lệnh Bash sử dụng AWS CLI để có thể dọn dẹp nhanh toàn bộ tài nguyên trên AWS CloudShell:

```bash
#!/bin/bash
# ==============================================================================
# KỊCH BẢN TỰ ĐỘNG DỌN DẸP TÀI NGUYÊN DỰ ÁN DAILY DATA LAKE
# Region: us-east-1 | Nhóm: 24110251 - 24110252
# ==============================================================================

REGION="us-east-1"
BUCKET_NAME="daily-datalake-24112051-24110252-2026"
GLUE_DB="daily_datalake_db"
GLUE_CRAWLER="daily-sales-crawler"
ATHENA_WG="daily-datalake-wg"
CW_ALARM="daily-datalake-high-scan-alert"

echo "1. Xoa CloudWatch Alarm..."
aws cloudwatch delete-alarms --alarm-names $CW_ALARM --region $REGION

echo "2. Xoa AWS Glue Crawler va Glue Database..."
aws glue delete-crawler --name $GLUE_CRAWLER --region $REGION
aws glue delete-database --name $GLUE_DB --region $REGION

echo "3. Xoa Amazon Athena Workgroup (Recursive)..."
aws athena delete-work-group --work-group $ATHENA_WG --recursive-delete-option --region $REGION

echo "4. Lam rong (Empty) va xoa S3 Bucket..."
aws s3 rm s3://$BUCKET_NAME --recursive --region $REGION
aws s3 rb s3://$BUCKET_NAME --force --region $REGION

echo "Hoan tat qua trinh don dep tai nguyen Data Lake!"
```

- [x] **Amazon CloudWatch:** Danh sách Alarms tại `us-east-1` hiển thị `0` alarm.
- [x] **Amazon EC2 & VPC:**

  - NAT Gateways = `0`.
  - Elastic IPs = `0`.
